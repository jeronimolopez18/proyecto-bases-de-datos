SISTEMA DE VENTAS POR INTERNET - Aplicación PHP (sin framework)
================================================================

Requisitos: Linux, PostgreSQL, PHP con las extensiones pdo_pgsql y mbstring
(en Ubuntu: sudo apt install php php-pgsql php-mbstring).
Si falta mbstring la aplicación igual funciona (trae un respaldo), pero se recomienda instalarla.


1. CREAR LA BASE (solo si no existe todavía)

   cd "/home/jeronimolopez/Bases De Datos/PROYECTO"
   sudo -u postgres psql < ventas_internet.sql


2. CREAR EL USUARIO QUE USA LA APLICACIÓN (una sola vez)

   cd "/home/jeronimolopez/Bases De Datos/PROYECTO/ventas_app"
   sudo -u postgres psql -d proyecto < usuario_app.sql

   Crea el usuario app_ventas con clave ventas2026. Si la cambias,
   cámbiala también en config.php.
   Si vuelves a ejecutar ventas_internet.sql (borra y crea la base),
   repite este paso.


3. INICIAR LA APLICACIÓN

   cd "/home/jeronimolopez/Bases De Datos/PROYECTO/ventas_app"
   php -S localhost:8000

   Abre en el navegador:  http://localhost:8000
   Para detenerla: Ctrl + C en la terminal.


ARCHIVOS
--------

includes/db.php       Conexión PDO y funciones para consultar
includes/funciones.php  Validaciones, mensajes y traducción de errores de PostgreSQL
includes/encabezado.php, includes/pie.php   Menú y pie comunes
css/estilos.css       Diseño de las pantallas
index.php             Inicio: indicadores, últimas ventas y stock bajo

articulos.php, categorias.php, clientes.php, ciudades.php   Registro, edición, consulta y borrado
usuario_app.sql       Usuario y permisos de la aplicación en PostgreSQL


CÓMO CUMPLE LOS REQUISITOS DEL PROYECTO
---------------------------------------
- PHP sin framework, sobre Linux, con PostgreSQL.
- Validación de datos de entrada: en el navegador (required, min, type)
  y en PHP antes de guardar (funciones validar_* de includes/funciones.php).
- Números no negativos: PHP lo valida y la base lo garantiza con CHECK
  (precio > 0, stock >= 0, cantidad > 0, monto > 0, id_cliente > 0).
- Fechas: el disparador trg_validar_fecha_pago impide un pago con fecha
  anterior a la venta; la app muestra su mensaje.
- Disparador: trg_descontar_stock_venta descuenta el inventario al agregar
  un artículo a una venta y la rechaza si no hay stock.
- Integridad referencial: al intentar borrar algo en uso (ciudad con
  clientes, cliente con ventas, artículo vendido, venta con pagos) la base
  lo impide y la app muestra un mensaje claro. Al corregir la cédula de un
  cliente, sus ventas se actualizan solas (ON UPDATE CASCADE).
- El total de cada venta no se guarda: se calcula con una consulta (3FN).

PRUEBAS RÁPIDAS PARA LA SUSTENTACIÓN
------------------------------------
1. Ventas > Ver una venta Pendiente > agregar un artículo con cantidad
   mayor al stock: sale "Stock insuficiente..." (disparador).
2. Registrar un pago con fecha anterior a la venta: sale el error del
   disparador de fechas.
3. Ciudades > Eliminar Villavicencio: no deja porque tiene clientes (RESTRICT).
4. Artículos > Nuevo con precio -5 o stock 2.5: la validación lo rechaza.
5. Registrar un pago aprobado por el total de una venta Pendiente: la venta
   pasa sola a estado Pagada. Si luego se elimina o rechaza ese pago, vuelve
   sola a Pendiente.
6. Registrar un pago mayor al saldo de la venta: la aplicación lo rechaza.
7. Cancelar una venta (Actualizar seguimiento > Cancelada): su stock vuelve
   al inventario y ya no recibe pagos.

ESTADOS DE UNA VENTA
--------------------
Pendiente -> Pagada (sola, al completar los pagos aprobados) o Cancelada
Pagada    -> Enviada o Cancelada (vuelve a Pendiente si deja de cubrir el total)
Enviada   -> Entregada
Entregada y Cancelada son estados finales.
Solo las ventas Pendiente o Pagada reciben, editan o eliminan pagos.
